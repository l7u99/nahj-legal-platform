# دليل التحقق والإطلاق — نهج القانوني

هذا الدليل خاص بفرع التطوير `safe/advocacy-submission-audit`. لا تُنفّذ خطوات قاعدة البيانات أو النشر قبل مراجعة طلب الدمج واعتماد خطة الإطلاق.

## 1. تحقق البناء والوظائف

يعمل GitHub Actions على طلبات الدمج ويشغّل:
- `npm install` ثم `npm run build` للتحقق من واجهة React.
- `deno check` لوظائف Supabase التالية:
  - `submit-advocacy`
  - `impact-assistant`
  - `admin-ai-usage`

نجاح بناء الواجهة وحده لا يعني أن وظائف Supabase أو قاعدة البيانات قد نُشرت أو اختُبرت على بيئة تشغيل.

## 2. متغيرات البيئة والأسرار

### متغيرات Vite في GitHub Actions
- `VITE_SUPABASE_URL`
- `VITE_SUPABASE_PUBLISHABLE_KEY`

### أسرار Supabase Edge Functions
- `OPENAI_API_KEY` — لمساعد أثَر فقط
- تقييم المرافعات الآلي معطّل عمدًا؛ لا يلزم إعداد سقف استخدام له.
- `IMPACT_AI_MONTHLY_LIMIT` — عدد طلبات مساعد أثَر المسموح بها شهريًا.
- `OPENAI_MODEL` — اختياري، الافتراضي `gpt-4o-mini`.

لا تضع أي مفتاح سري في ملفات المستودع أو متغيرات Vite التي تُضمّن في المتصفح.

## 3. ملفات ترحيل قاعدة البيانات

تُراجع الملفات التالية بالترتيب قبل تطبيقها على مشروع Supabase:
1. `20261127021000_create_impact_assessments.sql`
2. `20261127022000_add_advocacy_ai_usage_quota.sql` — ترحيل احتياطي قديم، غير مطلوب لتشغيل المسابقة مع تعطيل التقييم الآلي.
3. `20261127023000_expand_advocacy_scores_to_100.sql` — راجع الحاجة إليه مع مخطط قاعدة البيانات؛ لا يُطبّق قبل التأكد من توافق قيود الدرجات مع نموذج 15 درجة الموضوعية.
4. `20261127024000_add_impact_ai_usage_quota.sql`

الترحيل `20261127022000_add_advocacy_ai_usage_quota.sql` خاص بسقف تقييم المرافعات الآلي المعطّل حاليًا، ولذلك لا يُطبّق ضمن الإطلاق الحالي ما لم يُعَد تفعيل تلك الخدمة بقرار مستقل. لا تُطبّق أي ترحيلات قبل مراجعة المخطط الفعلي وأخذ نسخة احتياطية والتحقق على بيئة تجريبية. لا تُعدّل سجلات المشاركين الحالية.

## 4. اختبارات القبول قبل الإطلاق

### المرافعة
- تسليم مشاركة تجريبية والتحقق من حفظها دون استدعاء الذكاء الاصطناعي.
- التأكد من احتساب المراحل الموضوعية الثلاث من 15 درجة إجمالًا، وبقاء المرافعة الختامية بانتظار المراجعة البشرية دون استدعاء الذكاء الاصطناعي أو إنشاء درجة آلية.
- إعادة إرسال الطلب نفسه والتحقق من عدم إنشاء مشاركة ثانية أو تغيير بيانات المشاركة المحفوظة.
- التحقق خادميًا من حد المرافعة: 200 حرف على الأقل و5,000 كلمة كحد أقصى.
- التأكد من عدم عرض درجة آلية أو ترتيب نهائي قبل المراجعة البشرية.
- التأكد من أن ترتيب النتائج أولي ولا يُنشر كترتيب نهائي قبل المراجعة البشرية.

### منظومة أثَر
- تجربة كل بوابة من البوابات الثلاث.
- التأكد من أن التقرير لا يخترع أرقامًا أو مؤشرات عند نقص المعلومات.
- التأكد من أن التقرير لا يُحفظ إلا بعد طلب المستخدم المسؤول ذلك.
- التحقق من أن غير المسؤول لا يستطيع قراءة التقارير أو تعديلها.
- اختبار الطباعة وحفظ PDF.

### الصلاحيات والاستهلاك
- التحقق من أن سجلات الاستهلاك لا يمكن قراءتها من دور `anon` أو `authenticated` مباشرة.
- التأكد من أن سقف كل خدمة مستقل ويوقف الطلبات عند بلوغه.
- التأكد من عدم ظهور مفاتيح API أو تفاصيل داخلية في رسائل المستخدم.

## 5. حدود التحقق

- نجاح GitHub Actions يثبت نجاح خطوات CI فقط.
- لا يثبت نجاح الاتصال الفعلي بـOpenAI أو Supabase.
- لا يثبت تطبيق migrations أو نشر Edge Functions.
- لا يُعدّ الموقع جاهزًا للإطلاق حتى تُنفذ اختبارات القبول على بيئة تجريبية ويُراجع أثر التكلفة والصلاحيات.
